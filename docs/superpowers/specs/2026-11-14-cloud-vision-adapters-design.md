# 图片相似与人脸的云端 API 适配设计

日期：2026-11-14。状态：用户已批准推荐范围，正在实施。

## 用户目标

在手机版中，图片相似和人脸功能也能通过服务地址、API Key、模型名称调用云服务。
用户点名 DeepSeek、Qwen、B.AI；不是仅显示输入框，还需要真正适配请求与返回协议。
四项 AI 连接保持独立。

## 调研结论与支持边界

| 平台 | 图片相似 | 人脸定位 |
| --- | --- | --- |
| Qwen / 阿里云百炼 | 官方多模态向量接口已明确，首批适配 | 视觉模型支持物体定位，可接入并验证人脸框 |
| DeepSeek | 已查阅的官方文档中未找到图片向量接口，首批不宣称支持 | 官方当前 `deepseek-flash` 支持图片输入，可接入视觉请求；定位质量仍需实测 |
| B.AI | 已查阅的官方文档中未找到图片向量接口，首批不宣称支持 | 提供 OpenAI 兼容请求和视觉模型；需选账户实际可用、支持图片的模型 |

视觉聊天、图像生成、文本向量与图片向量是不同能力。图片相似继续使用真实图片向量，
不把模型生成的一串数字或图片文字描述当成原有图片向量。
这里的人脸功能维持封面裁剪对焦用途，不增加人物身份识别。

## 方案比较

1. **推荐：Qwen 图片向量 + 三家视觉请求适配。** 图片相似先使用有官方协议的百炼
   多模态向量接口；人脸增加 OpenAI 兼容视觉模式，提供 Qwen、DeepSeek、B.AI 预设。
   适配范围符合用户点名的服务；人脸可用性必须以实际坐标与图像测试结果判断。
2. **分阶段：首批只做 Qwen 两项。** 接口和定位能力的官方资料更完整，验证更集中，
   但 DeepSeek、B.AI 的人脸接入会留到后续。

两种方案均保留现有本地服务协议。用户已选择方案 1，并要求完成后使用模拟器验证。

## 设计审阅

已完成一次独立只读审阅。唯一需要用户确认的是首批采用推荐范围还是只做 Qwen；
除此之外未发现阻碍编写实施计划的重要缺项。确认本设计时一并选择范围即可。

## 推荐方案的界面

- 图片相似增加服务类型：现有图片向量服务、Qwen 百炼图片向量。
- 人脸增加服务类型：现有人脸服务、OpenAI 兼容视觉模型；提供三家地址预设并允许自定义。
- 两项均保留独立的服务地址、API Key、可手填模型名、连接测试。
- 现有开关行为保留：字段常显，关闭时禁用，开启后编辑。
- 预设仅帮助填入服务地址和合适的模型示例，不覆盖已保存的其他功能连接。
- 人脸视觉模式提供按当前连接查询模型；模型列表不等于模型已通过定位验证。
- 图片相似说明明确要求图片向量模型，避免误填普通聊天或文本向量模型。
- 覆盖现有简体中文、繁体中文、英文、日文、韩文文案。

## 请求与返回

### 图片相似

- 现有模式保留 `/v1/embeddings` 协议及已有认证、返回校验。
- 百炼模式调用官方多模态向量端点，发送 `model`、`input.contents[].image`；图片使用
  本地预处理后的 Data URI，不依赖手机图片的公开 URL。
- 使用该功能自己的 Bearer Key，解析 `output.embeddings`，选择本次图片的向量。
- 向量统一进行数值、维度、有限值、非零范数校验与归一化；不降低现有校验以换取成功。
- 以 `qwen3-vl-embedding` 等明确支持图片的模型为示例，模型名称仍允许手填。

### 人脸

- 现有模式保留 `/v1/faces`。
- 新增视觉模式调用 `/chat/completions`，图片放入 `image_url` 内容块，要求仅返回
  人脸位置的 JSON。分别使用该功能保存的地址、模型及密钥。
- 不支持图片的模型、拒绝处理、截断、空输出、无效 JSON 和越界/退化坐标均明确报错，
  不把错误当成“没有人脸”。合法空人脸列表与调用失败分开处理。
- 将坐标转为现有内部规范，继续进入原有人脸对焦流程；视觉模型定位精度需用真实图片验证。
- 视觉调用采用适合云端的超时；批量任务继续允许取消，并限制并发及重试。

### 地址处理

- Qwen 图片向量按原生协议构造路径，不能使用聊天接口地址拼接 `/v1/embeddings`。
- 人脸预设分别使用百炼 OpenAI 兼容地址、DeepSeek 官方基础地址、B.AI 的 `/v1` 基础地址。
- 接受规范基础地址或对应完整端点，保留中转服务的路径前缀，避免重复追加 `/v1`
  或请求后缀。未知协议明确拒绝，不根据 Key 格式猜测平台。

## 旧数据与索引

- 旧配置未设置服务类型时仍使用原协议，不改变已有地址、密钥或模型。
- 不为云服务继承标题翻译或 AI 标签的密钥。
- 保存、遮罩、主动清空和测试草稿沿用现有独立连接机制。
- 云向量索引身份包含服务类型、规范化地址、请求模型及实际返回的模型/维度，
  避免不同服务的同名模型或同维向量混用；不包含密钥。
- 更改向量服务或模型后提示需要重建，在新索引完成前保持原有规则推荐；不自动删除片库数据。
- API Key 变化本身不触发向量重建；人脸服务切换不自动全库重算，用户可主动执行。

## 测试与验收

- 用官方格式的本地 HTTP 测试服务覆盖百炼向量请求，以及三家人脸预设的路径、图片、
  模型、认证、返回转换；校验测试和实际任务使用同一连接解析。
- 覆盖认证失败、限流、超时、拒绝、无效/截断响应、空人脸列表、非法坐标及错误模型。
- 覆盖旧配置零变化、保存刷新、独立凭据、地址后缀去重、索引身份及切换后重建提示。
- 现有合成图案不能作为云服务必须检出真实人脸的依据。视觉模式的人脸测试使用用户
  主动选取的测试图片，并展示检出的框；没有测试图时不能声称定位质量已通过。
  不为此恢复演示照片或演示入口。
- 模拟器验证新服务选择、字段、保存刷新、测试和重建流程；使用隔离数据及假密钥。
- 没有真实厂商凭据时只报告协议验证结果，不宣称已完成厂商在线实测，也不读取其他
  App 的凭据进行测试。
- 完成相关回归、全量 Python 测试、JS 语法检查、Python 补丁回放和 Android Debug 构建。
