# 清爽原生 UI 与主页展示偏好设计

日期：2026-11-14

基线：v0.18.17-android-r10 / 8ab7285c

状态：用户已选定清爽原生风格、每行 2/3/5 部，以及独立的每页数量设置；本文用于确认实施范围。

## 已确认的目标

- 整体更换视觉风格，统一浏览、搜索、片库管理、设置、片库分析、说明六页及共用弹窗。
- 用户已从交互预览中选择“清爽原生”。
- 主页指浏览片库页 `/showcase`，加入随时可用的“显示”入口。
- 展示样式、每行数量、每页数量均可选，并记住选择。
- 每行数量严格提供 **2、3、5** 三项；用户刚明确此范围，不采用先前讨论的 1/2/3/4。
- 保留原有片库数据、维护能力、四项 AI 连接及批量任务流程。

## 方案比较与选择

1. 清爽原生：以封面网格为默认，采用不透明表面、细分隔线、适度圆角、清晰表单和统一橙色操作。手机操作直观，用户已选择。
2. 紧凑目录：列表为主、密集分隔线，文字信息更多；未选用。列表仍作为所选风格内的一种片库呈现方式。

这是现有 Python + Android WebView 项目的界面改造，不迁移技术栈，不增加 UI 框架。

## 视觉规则

- 浅色使用接近白色的不透明表面与浅灰背景；深色使用深灰背景与稍亮表面。
- 橙色继续用于主要操作及所有批量维护按钮；红色用于破坏性操作与错误，绿色用于成功提示。
- 统一间距为 4/8/12/16/24 像素层级；常规控件约 44–48 像素触摸高度。
- 统一系统字体栈，不依赖网络字体；保留用户现有的五档字号。
- 常规控件圆角约 10–12 像素，分组容器约 12–16 像素；不使用凸起阴影、装饰发光、玻璃模糊和背景渐变。
- 卡片、输入框、标签、开关、选项组、消息及弹窗使用同一套公共样式。修正旧规则冲突，不只在末尾堆叠新覆盖。
- 图标沿用仓库现有图标库，统一视觉尺寸和线条；无新增远程图标依赖。
- 小屏允许控件换行，禁止整页横向溢出；仅原有数据表格允许局部横向滚动。

## 主页展示控制

### 入口与样式

- 浏览页工具栏提供有可见文字的“显示”按钮，打开同一风格的设置面板。
- 提供横向封面、竖向海报、列表；保留现有表格视图的可达入口。
- 手机版可直接切换封面/海报/列表，不再被桌面专用显示门槛隐藏。
- 这几种呈现都属于清爽原生视觉风格，不需要切换整套主题。

### 每行 2/3/5 部

- 网格提供 2/3/5 三个等宽选项，选中立即更新 CSS 网格列数。
- 选择 5 列时依然保持 5 列，不因为旧媒体查询静默变回 3 列。
- 列表和表格中不应用列数，控件明确标示仅用于网格；返回网格恢复用户选择。
- 五列卡片只显示必要编号和短标题；避免在狭窄卡片中堆积演员、标签和多个操作图标。
- 卡片标题按有限行数截断，完整内容在原有详情中查看；不压缩文字以强塞一行。
- 卡片仍可整张点击，播放、分段、收藏及原有详情操作保留。
- 新用户默认竖向海报、每行 2 部，匹配用户选中的预览；已有明确选择优先保留。

### 每页影片数

- 独立提供 30/45/60/90/120 部，默认 45 部。原有非标准有效值需兼容读取，不在刷新时悄悄改写。
- 修改每页数量时回到第 1 页，保留搜索、排序与筛选，重新计算真实总页数。
- 修改样式或每行数量不改变每页数量；不会把所有影片加载出来代替分页。
- 仍按逻辑影片计数：同一完整分段组算 1 部。
- 当前源码手机网格上限为 **45**，且设置中的分页值不能在主页直接更改；应移除与显式用户选择冲突的截断逻辑。
- 保留并验证已有图片视窗：只请求附近封面，远离屏幕后释放图片元素，不同时解码一页全部高清封面。
- 120 部与五列组合必须实测滚动、翻页、筛选及返回后封面显示，不回退到历史空白封面问题。

### 保存与恢复

- 在主页更改后立即生效，并自动保存；无需进入设置页再点击保存。
- 刷新、切换页面及关闭重开 App 后恢复选择。
- 设置页的主页显示设置与主页保持一致，避免两个互相覆盖的来源。
- 失败时显示未保存状态并可重试，不能显示保存成功后重开丢失。
- 旧的浏览 localStorage 与配置需要一次性兼容，保留排序、收藏、筛选等无关偏好。
- 不将仅控制导出网页的 `gallery.default_mode` 误当作浏览页设置。导出网页与浏览页的既有分页关系由实现者检查后采用明确名称区分，不能重复显示含糊的“展示数量”。

## 页面落地

- 导航：紧凑顶栏，主要页面的固定导航与“更多”入口保持明确；不遗失搜索、分析、帮助入口。
- 浏览：清理工具栏，统一卡片和详情弹层，加入展示控制；保留人物墙与筛选能力。
- 搜索：统一输入框、来源控件、结果卡及空白/失败状态。
- 片库管理：压缩过度留白，统一目录组、别名组、缺失项、任务进度、橙色维护按钮和来源面板；保留先搜索简介后询问翻译的流程。
- 设置：语言、字号、主题控件作为一个整体居中；统一分组导航、四项 AI 表单和保存状态；所有输入框完整可见。
- 分析：统一文字、图表容器、筛选器和统计样式；保留既有图表语义及数量规则。
- 说明：使用相同标题、正文、分隔线及链接样式。
- 共用与原生弹窗：统一对齐、按钮层级、长文本换行及深浅色；保留关闭、返回键、焦点和未保存确认。

## 范围与边界

- 不改影片内容、抓取来源、AI 协议、NFO 写回、播放协议和数据库结构中的影片数据。
- 本轮实现与验证，不根据旧的“打包上传”指令自动发布新版本。
- 不重引入演示图片、演示入口、NFO 备份选项及用户之前要求移除的功能。
- 不删除工作区的历史截图、数据库和诊断文件。
- 本文中的默认值、控件圆角、字段命名与迁移细节是实现建议，用户可修正；具体拆分由实现者决定。

## 验收

- Android 模拟器逐页检查六页，分别覆盖浅色/深色、常规/最大字号。
- 中文简体、中文繁体、日文、英文均检查长标签、分组导航、按钮和弹窗，不以截图里中文正常代替多语言验证。
- 320/360/412 像素宽度检查横向溢出和错位，补横屏检查。
- 每行 2/3/5 实际测量列数，尤其 320 像素 + 最大字号下的 5 列；不靠 CSS 文本断言替代实际布局。
- 30/45/60/90/120 分页覆盖一批充足的逻辑影片，验证 API 返回、计数、末页、分段计数、刷新与重启持久化。
- 先前封面视窗、失败重试和翻页请求代次保护继续通过；观察 120 部滚动时图片元素数量和 JavaScript 错误。
- 运行与状态变更相关的回归测试、现有 Python 全量、所有 JS 语法、Python patch 回放验证、Android 单元与 Debug 构建。
- 测试前保存模拟器配置和数据，测试完成恢复；不操作真实片库。
