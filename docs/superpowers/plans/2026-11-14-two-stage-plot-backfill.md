# 分两步补齐简介

用户要求：先搜索并保存缺失简介，完成后询问是否翻译本次找到的简介。

设计：保留现有来源选择及三路并行。搜索阶段不初始化翻译服务，将原文写入空白 NFO 的 plot/originalplot；按逻辑影片记录本次实际写入的 NFO。完成后弹出“翻译 / 保留原文”，后者保留待翻译入口。翻译阶段仅处理这个批次，使用执行时的 App 语言及翻译设置，不再次搜索；简介已被编辑或翻译时跳过。失败保留原文，允许重试。批次记录保存在 App 数据目录，刷新后可继续。

实施选择：直接保存原文符合“搜索完成并添加之后询问”；预先询问或暂存到确认后才写入均不符合用户指定顺序。沿用当前功能分支，不改版本或发布。

- [ ] 后端：回归先失败；解耦搜索与翻译，持久批次和原文匹配保护，分段影片保持一部/各 NFO 更新。
- [ ] 前端：搜索不依赖翻译开关；完成弹窗及批次翻译入口、失败重试、五语言文案。
- [ ] 验证：两套全量 Python、JS、补丁回放、Debug 构建及专用模拟器验证两种选择。

重点检查：搜索期间无 AI 调用；翻译失败不丢原文；不翻译此前已有的简介；分段和部分写入失败；切换语言、刷新和重试；过期批次/手动编辑不被覆盖。
