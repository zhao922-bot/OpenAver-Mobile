# OpenAver Mobile 对齐 v0.18.17 分阶段计划

> 基线：`v0.17.18-android-r57`（commit `e144cb7`，versionCode `17075`）
> 目标上游：OpenAver 正式版 `v0.18.17`（commit `073780e`）
> 上游起点：`v0.17.18`（commit `af0d997`）
> 新移动端版本线：`v0.18.17-android-r1`、`r2`、……
> 文档日期：2026-11-11
> 状态：r1～r7 已实现，r7 已完成全量测试、模拟器验证和 arm64 构建

## 0. 摘要

本项目只对齐正式版 `v0.18.17`，不考虑上游 `main` 上尚未正式发版的 `0.19.0`。

`v0.17.18..v0.18.17` 共包含 292 个提交、391 个变动文件，其中 181 个新增、
209 个修改、1 个删除。移动端 r57 已经移除桌面运行时和桌面专属页面，因此不能把
上游仓库整体合并或直接快进，只能按功能逐项移植。

建议拆成 6 个可独立验收的版本：

1. `v0.18.17-android-r1`：补完性能、搜索正确性和来源修复。
2. `v0.18.17-android-r2`：片库修复、常收女优、图片轮换与标签体验。
3. `v0.18.17-android-r3`：韩文、设置页分页、说明页和新手引导。
4. `v0.18.17-android-r4`：截图查番号、OpenAI 官方翻译和灯箱简介。
5. `v0.18.17-android-r5`：远端人脸和封面相似。
6. `v0.18.17-android-r6`：AI 标签和入库后自动化。
7. `v0.18.17-android-r7`：缺失简介批量抓取、全文翻译与写回。

### 版本号规则

- GitHub tag：`v0.18.17-android-rN`。
- `versionName`：`0.18.17-rN`。
- 新版本线从 `N=1` 重新开始。
- Android `versionCode` 不能重置，必须继续大于旧版本线的 `17075`。
- 建议新版本线从 `18001` 起递增：r1=`18001`、r2=`18002`，以此类推。
- `versionCode` 与公开版本号分开管理，避免覆盖安装时被 Android 判定为降级。

每个版本都必须单独构建、单独验收。除非明确要求，不在计划执行过程中直接提交、
打 tag 或发布 GitHub Release。

## 1. 对齐定义

### 1.1 本计划包含

- 移植 `v0.18.17` 中适用于 Android 移动端的功能、行为修复和用户界面。
- 同步与这些功能直接相关的 Python 后端、Web 前端、语言资源和 Android 原生资源。
- 保留移动端现有的 Android 文件系统、播放器、后台任务和本地服务实现。
- 为新增功能补充回归测试和模拟器验证。

### 1.2 “对齐”不等于

- 不要求源码与上游逐文件相同。
- 不搬运 Linux 服务器、PyWebView、Connect、托盘、自动更新器等桌面设施。
- 不照搬桌面端布局；移动端只对齐能力和行为。
- 不整体替换移动端依赖清单。

### 1.3 本计划不包含

- 不考虑 `0.19.0`。
- 不实现影片真实解析度、编码、码率、帧率或真实片长。
- 不增加 `pymediainfo`、`media_probe`、`resolution-tier` 或相关数据库字段。
- 不恢复 r56/r57 已删除的桌面运行时和桌面专属页面。
- 不整体升级 Pydantic、Pillow、lxml、curl_cffi 或 websockets。
- 不对已发布 tag 做 amend、force-push 或改写。

> 核对结果：`v0.18.17..main` 有 66 个变动文件，主要就是 `0.19.0` 的影片真实信息
> 功能。该范围已全部排除。

## 3. 执行原则

1. **按功能 cherry-pick 或手工移植**，不整体 merge 上游。
2. 先移植 `core/` 的纯逻辑，再接 `web/routers/`，最后接模板、JS、CSS 和语言文件。
3. 移动端已有定制逻辑优先保留，尤其是分段视频、Jable、标题翻译和文件写回。
4. 新增长任务必须接入现有前台保活 Service，不依赖 WebView 持续可见。
5. 每次修改 `app/src/main/python` 后都必须重新生成并校验 Python patches。
6. 工作区中的历史诊断文件不提交、不删除，禁止 `git add -A`。
7. 每个版本只处理本计划列出的范围，不在同一版本夹带无关重构。

## 7. r4：截图查番号、官方翻译与灯箱简介

### 7.1 目标

加入 `v0.18.13` 的图片查番号，以及 `v0.18.7`～`v0.18.10` 中与普通用户直接相关、
但不依赖 AI 标签后台系统的功能。

### 7.2 任务

| ID | 任务 | 优先级 | 风险 | 主要区域 |
| --- | --- | --- | --- | --- |
| D1 | 选择图片/封面查番号 | P1 | 中高 | `core/avscan/*`、image-search UI |
| D2 | OpenAI 官方翻译 | P1 | 低 | config、openai client、settings |
| D3 | 灯箱读取 NFO 简介并翻译 | P2 | 中 | plot_nfo/writeback、showcase plot |

### 7.3 截图查番号移动适配

- 手机主入口为 `<input type="file">`，支持 JPG、PNG、WEBP。
- 首次使用必须提示图片会发送到第三方 `avscan.cc`。
- 超过大小限制时先在本地缩放，最终上限 8MB。
- 全局限速为同时最多 1 张、两次间隔至少 5 秒。
- 图片不写入相册、数据库或应用缓存，失败后释放 object URL。
- 返回最多 5 个候选，显示相似度、匹配时间点、是否已在片库。
- 无明确命中时不能自动整理或搬动文件。
- 代理范围仅在用户设置为“全部来源”时对 avscan 生效。

### 7.4 灯箱简介

- 从 NFO `<plot>` 读取简介，不回写空值。
- “翻成当前语言”复用现有翻译服务，翻译结果按用户操作决定是否写回。
- 切换语言或影片时取消晚到翻译，不覆盖下一部影片。
- 旧影片没有 NFO 简介时显示明确空状态，不触发批量网络请求。

### 7.5 验收标准

- Android 文件选择器可选本地截图并成功得到候选。
- 拒绝隐私提示时不发起网络请求。
- 取消查询后晚到响应不改变页面。
- 5 秒限速、图片大小、格式和代理范围测试通过。
- OpenAI 官方模型列表、测试翻译和实际补翻译均可用。
- 简介读取、原文/译文切换、停止与错误回退正常。

### 8.3 移动端约束

- 只支持 HTTP/HTTPS 远端服务，不在手机内运行模型。
- 服务 URL、API Key 和模型名存储在本地配置中，不写入日志。
- 人脸端点失败时退回现有内置人脸对焦。
- 相似索引支持开始、停止、进度、失败原因和增量补跑。
- 长任务通过现有 `TaskKeepAliveService` 保持运行并显示通知。
- 离开页面或切到桌面不能中断任务。

### 8.4 验收标准

- 设置页可以测试连接并区分网络、认证、响应格式和模型错误。
- 人脸服务可用时使用远端结果，不可用时自动回退。
- 相似索引中断后可在原进度继续，不重复索引已成功项。
- 相似筛选只展示真实返回结果，不阻塞普通片库浏览。

## 10. 依赖与安全边界

| 依赖 | 上游 v0.18.17 | 移动端策略 |

## 11. 必须保护的移动端定制

每个阶段都要执行以下回归：

- 分段视频在所有用户界面按 1 部计算，底层仍逐文件写 NFO、封面和剧照。
- Jable 来源仍可启用、搜索、抓标签和参与来源排序。
- 补翻译严格按当前 UI 语言判断，繁中标题在简中模式下仍会翻译。
- 统一命名同步数据库标题、`original_title` 和 NFO，不丢失已翻译标题。
- 缺少 NFO 时仍能在最终文件夹内生成标题 NFO。
- 普通和分段视频都提供“外部播放器/内置播放器”选择。
- Android 原生菜单、确认框、播放器选择和通知继续跟随 App 内语言。
- 长任务切到桌面后仍通过前台 Service 继续执行。

## 13. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 整体合并上游导致桌面代码回流 | 高 | 只按文件和功能移植 |
| 上游代码覆盖分段/Jable/标题翻译逻辑 | 高 | 每阶段先写回归测试再移植 |
| 韩文只改 Web、原生仍中文 | 中 | Web + Android strings + 模拟器双端验收 |
| 截图查番号产生隐私争议 | 中 | 明确第三方提示，拒绝则不请求 |
| AI 功能造成重复费用 | 中 | 幂等记录、手动开关、费用提示 |
| 长任务被杀后台 | 中 | 复用前台 Service、进度持久化 |
| Pillow 无法在 Chaquopy 升级 | 中 | 单独 wheel 预研，作为图片上传发布门槛 |
| 设置页分页导致未保存数据丢失 | 中 | 单一表单状态、切页不销毁、补状态测试 |
| 批次搜索或补完卡死 | 高 | 超时、停止、断点恢复和失败隔离测试 |
